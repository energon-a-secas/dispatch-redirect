# dispatch-redirect

Serves `dispatch.neorgon.com` and sends every request to
[antenne.neorgon.com](https://antenne.neorgon.com/), path and hash intact.

Live: <https://dispatch.neorgon.com/>

Dispatch was renamed to Antenne on 2026-09-23. This repo exists so bookmarks,
indexed links, story permalinks and feed subscriptions keep working. It holds no
application code.

## What it serves

| Path | What it does |
|---|---|
| `/` | Meta refresh plus `location.replace`, both to `https://antenne.neorgon.com/` |
| anything else | `404.html` does the same, carrying the requested path across |
| `/feed.xml` | A one-item RSS feed whose `atom:link rel="self"` is the new feed |
| `/robots.txt` | Crawlable on purpose, so a crawler can read the canonical |
| `/sitemap.xml` | The old root, so the move is discoverable from the old host |

Story permalinks are of the form `/#p=<story-id>` and the ids did not change, so
the JavaScript hop carries `location.hash` across and an old link lands on the
same story under the new domain. The meta refresh is the fallback for a reader
with JavaScript off; it reaches the new home page rather than the story, which
is the best a `<meta http-equiv="refresh">` can do, since a fragment never
reaches the server.

## It publishes nothing

The feed here is written by hand and gains no further items. Antenne's real feed
is generated by `build-feed.py` in the Antenne repo and is the only one that
grows. The single item in this file exists to explain the move to a reader that
is still subscribed to the old address; the 31 stories published before the
rename are not repeated, because reprinting their guids under a second host
would re-deliver the whole back catalogue to everyone who kept the old
subscription.

## How long it stays

Keep it for **at least a year**, to 2027-09-23. Redirects have to outlive the
links pointing at them, and the ones that matter here are outside anyone's
control: search results, other people's bookmarks, and feed readers that only
re-check on their own schedule.

It may be deleted when all three are true:

1. Search Console reports no impressions on `dispatch.neorgon.com` for a full
   quarter.
2. Nothing in the fleet still links the old domain (`grep -r dispatch.neorgon.com`
   across the monorepo returns only dated records).
3. Analytics shows no feed fetches against `/feed.xml` on this host.

Deleting it means deleting the repo, the Pages site, and the Namecheap CNAME for
`dispatch`, in that order. Until then the record stays: it is also what makes a
rollback to the old domain instant.
